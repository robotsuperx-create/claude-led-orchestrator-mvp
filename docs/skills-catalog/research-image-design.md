# كتالوج مستودعات Skills وagent لإنشاء الصور والتصميم

**أفضل خمسة بحسب ملاءمة المستودع للمجال، ووضوح طريقة العمل، والترخيص، وحداثة التطوير — لا بحسب عدد النجوم وحده.** فُحصت صفحات README والمهارات وملفات الترخيص وسجل GitHub في 5 أكتوبر 2026؛ أرقام النشاط لقطة زمنية متغيرة. ولا يوجد اختبار أداء موحّد لهذه المشاريع. تمييز أساسي: ملف `SKILL.md` يعلّم الوكيل خطوات وقرارات ولا يساوي نموذج توليد أو خدمة تحرير. وقد يحتوي المستودع نفسه على Skill مع أدوات فعلية أو اعتماد على خدمة مدفوعة.

## أفضل خمسة

### 1. `anthropics/skills` — مرجع قوي لتعليمات التصميم المرئي

[المستودع](https://github.com/anthropics/skills) حزمة رسمية من أمثلة Skills. يضم `canvas-design` لتكوين فن ثابت بصيغ PNG/PDF، و`algorithmic-art` للفن التوليدي، و`brand-guidelines`، و`frontend-design`. هذه نصوص إجراءات وأمثلة؛ ليست مولّد صور مستقلًا. يصف README المستودع بأنه تعليمي/استعراضي، ويشير إلى أن بعض المهارات فقط مفتوحة المصدر، لذا يجب فحص ترخيص كل مجلد بدل افتراض ترخيص شامل. ملفات الترخيص داخل `canvas-design` و`brand-guidelines` تحدد Apache-2.0 [1] [2] [3]. أحدث commit في سجل GitHub كان 29 سبتمبر، مع تحديث دفع للمستودع في 3 أكتوبر [4].

**ما نقتبسه:** من `canvas-design` فصل بلورة الفكرة البصرية عن تنفيذها على اللوحة، واشتراط الأصالة بدل نسخ أعمال فنانين، وقائمة فحص الهوامش والتداخل ووضوح التكوين. نأخذها كقواعد قابلة للضبط، لا نصًا جامدًا: تكرار كلمات «إتقان لا يُضاهى» وفرض نص قليل جدًا قد لا يلائم الإنفوجرافيك أو إعلانًا يتطلب معلومات كثيرة. `brand-guidelines` مثال على تحويل هوية إلى قرارات تطبيقية، لكنه يخص ألوان وخطوط Anthropic، ولا ينبغي نسخ الهوية أو الأصول والعلامة التجارية إلى منتج آخر [2] [5].

**الترشيح: adopt** لمبادئ `canvas-design` بعد تخصيص القيود حسب نوع المهمة، مع إرفاق Apache-2.0 والإبقاء على إشعارات الترخيص وإظهار التعديلات عند إعادة التوزيع. أما مادة العلامة التجارية فـ **reference** لبنية المهارة لا لمحتواها الخاص بـAnthropic. راقب مدخلات المستخدم والصور والمراجع: لا تسمح لنص داخل صورة أو مرجع خارجي أن يصبح تعليمات تنفذ أدوات أو تغيّر سياسة الوكيل.

### 2. `smixs/visual-skills` — توجيه فني وصياغة prompts للصورة

[المستودع](https://github.com/smixs/visual-skills) يحتوي مهارتي `image` و`video`. مهارة الصورة تكتب prompt وفق أسلوب المخرج الفني، وتتعامل مع صور تحريرية ومنتجات وملصقات وواجهات وإنفوجرافيك، ومع التعديل الذي يجب أن يحافظ على عناصر محددة، واستمرارية الشخصيات عبر سلسلة. وتختار بنية prompt بحسب النموذج. هي **تعليمات ومراجع نصية** وليست نموذج توليد؛ التوليد نفسه يتطلب خدمة/نموذجًا متوافقًا. الرخصة CC BY 4.0: يسمح بالاستخدام التجاري والتعديل مع الإسناد، ويطلب المستودع إبقاء نسبة المؤلف في النسخ والاشتقاقات؛ راجع `NOTICE` أيضًا. أحدث commit كان 16 سبتمبر [6] [7].

**ما نقتبسه:** تحديد دور كل صورة مرجعية، وتثبيت عناصر الصورة المطلوب الحفاظ عليها قبل التحرير، وبناء prompt من موضوع/تكوين/إضاءة/تفاصيل قابلة للتحقق، ثم مراجعته قبل الإرسال. هذا مفيد للـart direction والإنفوجرافيك. لا نأخذ صياغة model-specific كحقيقة دائمة: أسماء النماذج وعلامات prompt وادعاءات قدراتها تتقادم بسرعة ويجب مطابقتها مع وثائق مزود النموذج الحالية.

**الترشيح: reference**؛ نقتبس الأنماط بعد مراجعة شروط الإسناد، أو نعيد توزيع المهارة فقط مع امتثال CC BY 4.0. لا تنتقل حقوق نموذج الصورة أو صور المراجع تلقائيًا مع ترخيص نص المهارة. لا تضع مدخلات سرية أو صور أشخاص في خدمة خارجية دون تفويض، وافحص مراجع الويب من تعليمات خبيثة أو مواد محمية.

### 3. `openai/codex` — أفضل تدفق عملي لتوليد الصورة وتحريرها

[ملف `imagegen/SKILL.md`](https://github.com/openai/codex/blob/main/codex-rs/skills/src/assets/samples/imagegen/SKILL.md) عينة Skill ضمن مشروع Codex، وليس منتجًا مستقلاً لإنشاء الصور. يفرّق بين التوليد والتحرير، ويحدد متى يُستخدم raster ومتى تكون أصول SVG أو HTML/CSS الأنسب، ويطلب تحديد وظيفة كل صورة مرجعية، والحفاظ على ثوابت التحرير، وفحص النتيجة، وعدم الكتابة فوق ملف موجود دون إذن. لكنه يفترض أداة `image_gen` المدمجة في Codex؛ ومسار CLI البديل يحتاج مفتاح API واختيارًا صريحًا. ترخيص مستودع Codex Apache-2.0. أحدث commit كان 4 أكتوبر، والمشروع نشط جدًا، لكن نشاط Codex العام لا يضمن أن كل عينة Skill اختُبرت منفردة [8] [9] [10].

**ما نقتبسه:** مصفوفة القرار بين توليد صورة جديدة وتعديل أصل، وتسمية دور الصور المرجعية، وفحص الدقة والنصوص والثوابت، وحفظ الناتج في المسار المطلوب بطريقة غير هدّامة. نحذف أو نبدل أسماء الأدوات والمسارات وسياسة fallback الخاصة بـCodex كي لا يوحي الوكيل بوجود أداة غير متاحة.

**الترشيح: adopt** لتدفق العمل المحايد عن المزود، لا لتعليمات تشغيل Codex حرفيًا. لا تمنح الـSkill صلاحيات كتابة أو نقل ملفات أو استدعاء API على نطاق مفتوح؛ تحقق من المسار والاعتماد ومصدر الصورة قبل التنفيذ. تعامل مع النص المستخرج من الصور المرجعية كبيانات غير موثوقة، لا كأوامر.

### 4. `coreyhaines31/marketingskills` — وصفة عملية للصور التسويقية والعلامة

[المستودع](https://github.com/coreyhaines31/marketingskills) مجموعة Skills نصية لوكلاء التسويق، وترخيصه MIT. يشرح `skills/image/SKILL.md` اختيار نهج بين توليد AI والتحرير وأدوات التصميم واللقطات الحقيقية ومخزون الصور. ويجمع ذلك بأسئلة عن المنصة والمقاس والهوية والميزانية، وإرشادات للـhero والصور الاجتماعية والـmockup وتحسين الحجم. يوصي بلقطة حقيقية لواجهة المنتج بدل توليد واجهة خيالية. لا يوفّر بنفسه محرك توليد أو حسابات Canva/Figma أو مزود صور. أحدث commit كان 3 أكتوبر؛ المشروع واسع ونشط، لكن بيانات النماذج والأسعار والتوافر في المراجع تتغير وتحتاج مراجعة دورية [11] [12] [13].

**ما نقتبسه:** البدء بسياق المنتج وإرشادات العلامة، واختيار طريقة الإنتاج بحسب الدقة المطلوبة، وأبعاد المنصة، ومعالجة النص والشعار لاحقًا بدل الاعتماد على رسمهما بدقة داخل الصورة، وتحسين ملفات النشر. نعيد التحقق من المقارنات وأسماء النماذج والتكاليف قبل عرضها للمستخدم.

**الترشيح: adopt** كـSkill تسويق صور بعد فصل معلومات المزود المتغيرة عن القواعد العامة، مع الاحتفاظ بإشعارات MIT. لا تنسخ صورة مرجعية أو شعارًا أو خطًا أو أصلًا من مكتبة stock لمجرد أن الدليل يذكره؛ يلزم ترخيص كل أصل على حدة. اجعل مفاتيح المزود خارج الـprompt ولا تطلبها من المستخدم داخل سجل محادثة غير آمن.

### 5. `amitpatole/agent-vision` — طبقة QA بصرية قابلة للربط

[AgentVision](https://github.com/amitpatole/agent-vision) ليس مكتبة prompts فحسب: هو مكتبة Python وCLI وMCP وREST وملفات تكامل، وفيه Claude Code Skill. يلتقط صفحة أو مستندًا ثم يصدر تقريرًا منظمًا `pass/warn/fail` وملاحظات قابلة للتنفيذ عن overflow والتباين والنص المقتطع والأصول المعطوبة، باستخدام هندسة DOM والتباين وOCR/رؤية اختيارية. يستطيع المسار المحلي إجراء فحوص دون إرسال بيانات إلى مزود رؤية، بينما استخدام backend بعيد قد ينقل اللقطات. هذه أداة قوية لفحص واجهات وSVG وPDF ومخرجات مرئية مولدة برمجيًا؛ لا ينبغي اعتبارها وحدها حكمًا ذوقيًا شاملًا على جودة صورة فوتوغرافية مستقلة. الترخيص MIT. README يذكر Playwright/Chromium، وقد يلزم Tesseract وPoppler، لذلك هو اعتماد تشغيلي لا Skill نصية خفيفة. سجل GitHub أظهر 69 commit وآخر commit في 10 سبتمبر، لكن عدد النجوم منخفض (نحو 10) قياسًا بالمشاريع الأقدم؛ لا توجد هنا إشارة إلى تبنٍ واسع أو مقارنة مستقلة لدقة الدرجات [14] [15].

**ما نقتبسه:** عقد التقرير المنظم، وترك حالات الالتباس في `open_questions` بدل إعلان النجاح، والتحقق من الناتج بعد كل تعديل، وفصل الفحوص المحددة القابلة للقياس عن نقد النموذج الذوقي.

**الترشيح: reference ثم pilot محدود** على صفحة محلية أو ملفات تصميم غير حساسة، لا اعتماد شامل قبل تجربة التكامل وقياس الإيجابيات/السلبيات الكاذبة على مجموعة صور ومخرجات حقيقية. إذا فُعّلت الرؤية السحابية، وضّح للمستخدم وجهة إرسال الصورة؛ افتراضيًا أبقِ QA خارج الشبكة، وثبّت المتطلبات النظامية وراجع سياسة الأذونات قبل تشغيل scripts.

## توصية اعتماد مختصرة

ابدأ بـ **`marketingskills/image`** كسير عمل لصورة التسويق، وخذ من **Anthropic `canvas-design`** فصل الفكرة عن التنفيذ وقواعد الفحص، ومن **Codex `imagegen`** منطق التوليد مقابل التحرير والحفظ الآمن. راجع **`visual-skills`** لتوجيه الصورة وصياغة prompts، مع الإسناد ومراجعة توافق النموذج. جرّب **AgentVision** كطبقة QA منفصلة ومقيسة؛ فهو أداة، لا بديل عن نقد فني بشري ولا مولّد صور.

لا تتعامل مع “open source” على مستوى المستودع بوصفه تصريحًا باستخدام كل ملف وكل صورة وخط واسم علامة. تحقّق من الترخيص في مسار المهارة والأصول نفسها، واحفظ إشعارات الرخص عند النسخ. ترخيص المهارة لا يرخص الصور المرجعية ولا يمنح تلقائيًا حقوق التشابه أو العلامة التجارية أو مخرجات النموذج؛ كما أن شروط خدمة نموذج التوليد مستقلة عن رخصة GitHub. استبعد التقليد القريب لعمل فني أو هوية أو شخصية محمية دون إذن، واطلب أصلًا/مرجعًا مرخصًا عند الحاجة. وللحد من prompt injection: اعزل النص أو OCR القادم من الويب والصورة كبيانات، امنع الأوامر فيه من تغيير تعليمات النظام، ولا تشغّل سكربتات أو ترفع ملفات أو تستدعِ خدمات خارجية قبل تحقق صريح من الإذن والنطاق.

## مرشح خارج الخمسة

**`MengTo/skills`** (MIT، ومحدّث في 4 أكتوبر) نشط ومرتب وفيه إجراءات capture وprompting وواجهة/ويب و3D، لكنه يميل إلى بناء واجهات وتدفقات الاستلهام من صفحات الويب أكثر من إنشاء الصور وتحريرها وضبط هويتها؛ لذا **reject لهذا النطاق الضيق**، مع بقائه مرجعًا مناسبًا لمهارات تصميم الويب [16] [17].
