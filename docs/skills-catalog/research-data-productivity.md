# أفضل أدوات الوكلاء والمهارات وسير العمل للإنتاجية والبيانات

**تاريخ فحص المستودعات والرخص والنشاط: 5 أكتوبر 2026.** الترتيب يوازن بين تغطية الاحتياجات المذكورة، قابلية الاستضافة الذاتية، وضوح الرخصة، والنشاط الظاهر في سجل GitHub؛ وهو ترشيح عملي لا ترتيب بعدد النجوم.

## أفضل خمسة

### 1. Hermes Agent — وكيل عام بمهارات وذاكرة وأتمتة

[NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent) هو أقوى مرشح إذا كان المطلوب «وكيلًا واحدًا» يجمع تنفيذ الأدوات والمهارات والذاكرة والبحث والأعمال المجدولة. يصف README مهارات قابلة للتحميل، وذاكرة واسترجاعًا للمحادثات السابقة، وجدولة cron، وتفويض مهام لوكلاء فرعيين، وواجهات طرفية ورسائل متعددة. رخصة المستودع **MIT**، وسجل GitHub أظهر تحديثات في 4 أكتوبر 2026.[1] [2] [4]

للجداول، يتضمن المستودع مهارة `excel-author` بترخيص **Apache-2.0** تنشئ ملفات XLSX باستخدام `openpyxl`، مع صيغ قابلة للتدقيق، وتعليقات للمصادر، وفحوص اتساق. لكنها موجهة أساسًا إلى النماذج المالية، وليست بديلًا عن تحليل البيانات العام أو Excel كامل الميزات.[3]

**الفائدة:** نقطة تشغيل موحدة للبحث المتكرر، والتلخيص، والمهام المؤتمتة، مع قابلية إضافة مهارة خاصة بإجراءات المؤسسة. **المخاطر:** يستطيع الوكيل تشغيل أوامر والتعامل مع الملفات؛ والمهارات والبرمجيات الخارجية قد توسّع الصلاحيات. اعزله في حاوية أو حساب محدود، وافرض موافقة بشرية على الكتابة والحذف والإرسال قبل السماح بالتشغيل الدوري.

### 2. Jupyter AI — مساعد داخل دفاتر Python

[Jupyter AI](https://github.com/jupyterlab/jupyter-ai) إضافة لـJupyterLab توصل الوكلاء بالدفاتر الحاسوبية. يدعم واجهة محادثة داخل Jupyter، وإعطاء سياق من الملفات أو خلايا الدفتر، واستخدام الأدوات لتعديل الملفات وتشغيل الأوامر والتفاعل مع الدفاتر. يذكر المشروع نظام موافقات قبل الكتابة أو التنفيذ، وإمكان إضافة أدوات MCP ووكلاء متوافقين مع ACP. رخصته **BSD-3-Clause**، وأظهر سجل النشاط تحديثات في 3 أكتوبر 2026؛ والمشروع ما زال تحت الاحتضان في منظمة JupyterLab.[5] [6] [7]

**الفائدة:** يبقي التحليل في بيئة Python قابلة لإعادة التشغيل والمراجعة؛ مناسب للاستكشاف والتنظيف والتصور وشرح الشيفرة. **المخاطر:** جودة النتائج تعتمد على النموذج ومكتبات Python والبيانات؛ وقد يولّد الوكيل شيفرة خاطئة أو تنفيذًا غير آمن. ابدأ بدفاتر اختبار، وثبّت الاعتماديات، وراجع الخلايا قبل تشغيلها على بيانات إنتاجية.

### 3. Activepieces — أتمتة تكاملات الأعمال وسير العمل

[Activepieces](https://github.com/activepieces/activepieces) منصة مرئية لبناء تدفقات من المشغلات والإجراءات، مع وكلاء AI وتكاملات جاهزة. يذكر README موصلات لخدمات منها Google Sheets، وإمكان الاستضافة الذاتية، وفروعًا وتكرارًا ومحاولات إعادة وتدخلًا بشريًا. الأجزاء خارج مجلدات Enterprise مشمولة بـ**MIT**؛ أما `packages/ee` وبعض واجهات Enterprise فلها رخصة تجارية منفصلة. سجل المستودع أظهر تغييرات في 4 أكتوبر 2026.[8] [9] [10] [11]

**الفائدة:** الأنسب للأتمتة المتكررة بين التطبيقات، مثل استقبال ملف، والتحقق منه، وتحديث ورقة، ثم طلب موافقة. ويمكن تطوير موصلات إضافية بإطار TypeScript. **المخاطر:** لا تخلط بين ترخيص Community Edition ومكوّنات Enterprise؛ وافحص قائمة المزايا التي تعتمد عليها قبل النشر. كما أن رموز OAuth والأسرار والصلاحيات الواسعة تجعل عزل بيئة التنفيذ وتدقيق سجلات التشغيل ضروريين.

### 4. MarkItDown — قراءة مستندات PDF وOffice في خطوط البيانات

[Microsoft MarkItDown](https://github.com/microsoft/markitdown) مكتبة Python وأداة CLI تحوّل PDF وWord وExcel وPowerPoint وHTML وصيغًا أخرى إلى Markdown مناسب للبحث والتحليل بواسطة النماذج. المستودع **MIT**، وكان سجل commits نشطًا حتى 4 أكتوبر 2026.[12] [13] [14]

**الفائدة:** طبقة إدخال صغيرة ومباشرة قبل الفهرسة أو التلخيص، وتساعد على توحيد المستندات في صيغة نصية قابلة للمعالجة. **المخاطر:** هدفها استخراج المحتوى لا حفظ التطابق البصري أو إعادة إنشاء ملفات Office. كما أن التحويل العام قد يصل إلى ملفات أو عناوين شبكية بصلاحيات العملية؛ لذلك شدّد README على تنقية المدخلات غير الموثوقة واستخدام أضيق واجهة تحويل ممكنة. وللجداول، لا تعتمد على Markdown وحده إذا كانت الصيغ أو التنسيقات أو العلاقات بين الأوراق مهمة.

### 5. Khoj — بحث شخصي في المستندات والويب

[Khoj](https://github.com/khoj-ai/khoj) يجمع البحث الدلالي في المعرفة الشخصية مع الإجابة من الويب، ودعم ملفات PDF وMarkdown وWord وNotion وصيغ أخرى، وإنشاء وكلاء وإشعارات ونشرات بحثية. يمكن استضافته ذاتيًا، لكن ترخيصه **AGPL-3.0**؛ راجع التزامات التوزيع والتعديلات إذا ستقدمه كخدمة أو تدمجه في منتج. المشروع يشهد نشاطًا في المشكلات المفتوحة حتى أكتوبر، بينما تعرض صفحة سجل commits آخر تغييرات ظاهرة في 2 أغسطس 2026.[15] [16] [17] [19]

**الفائدة:** خيار متخصص لـ«الدماغ الثاني» والبحث عبر الملاحظات والوثائق ومصادر الويب، خصوصًا لمن يريد إبقاء الفهرس داخل بيئته. **المخاطر:** أوقفت الجهة المشغلة خدمة Khoj Cloud في 15 أبريل 2026، وأعلنت استمرار النسخة مفتوحة المصدر ذاتية الاستضافة مع تركيزها على منتجات أخرى مثل Pipali وOpen Paper. لذلك أوصي بـKhoj فقط للاستضافة الذاتية، مع اختبار النسخ الاحتياطي والترقية، وعدم بناء اعتماد حرج عليه قبل التحقق من اتجاه صيانته.[18]

## ترشيح مكدس عملي

- **تحليل البيانات:** JupyterLab مع Jupyter AI، ودفاتر Python تعتمد `pandas` و`numpy` و`matplotlib` أو `seaborn`. احفظ البيانات الخام للقراءة فقط، وسجّل التحويلات في خلايا قابلة لإعادة التشغيل.
- **PDF وملفات Office:** استخدم MarkItDown للاستخراج النصي والفهرسة، لا للتحويل الطباعي أو للحفاظ على دقة التخطيط. للمستندات الممسوحة أو المحتوى الذي يعتمد على الجداول والصور، اختبر OCR ومحللًا متخصصًا على عينات فعلية قبل اعتماد خط الإدخال.
- **جداول البيانات:** حلّل CSV/XLSX بـ`pandas`، واستخدم `openpyxl` لإنشاء XLSX عند الحاجة. يمكن استعارة مهارة `excel-author` المرخصة Apache-2.0 من Hermes للنماذج المالية القابلة للتدقيق؛ أعد حساب الصيغ وافحص الناتج في LibreOffice أو Excel، لأن كتابة الصيغة وحدها لا تضمن احتسابها في كل مستهلك.[3]
- **المعرفة والبحث:** جرّب Khoj ذاتي الاستضافة لمجموعة محدودة من المستندات والملاحظات إذا كان تقبّل انتقال المشروع ورخصة AGPL مناسبًا. احتفظ بنسخ المصدر خارج قاعدة الفهرسة، واختبر أجوبة الاسترجاع بمراجع قابلة للنقر بدل قبول الملخصات بلا تحقق.
- **التشغيل والأتمتة:** استخدم Activepieces للخطوات الحتمية بين التطبيقات—مثل مشغل، تحقق من الحقول، تحديث Sheet، ثم موافقة بشرية. أضف Hermes للمهام التي تحتاج بحثًا أو حكمًا لغويًا، لكن افصل صلاحياته عن تدفقات الكتابة الآلية.

## ملاحظات ترخيصية مهمة

مستودع [Anthropic Skills](https://github.com/anthropics/skills) مفيد كنموذج لبنية المهارة و`SKILL.md`؛ لكن README يوضح أن مهارات إنشاء وتحرير DOCX وPDF وPPTX وXLSX الموجودة فيه **متاحة للاطلاع وليست مفتوحة المصدر**. لا تنقلها إلى منتج أو تصفها بأنها مفتوحة المصدر دون مراجعة شروط كل ملف. في المقابل، مهارة `excel-author` داخل Hermes موسومة صراحةً بـApache-2.0.[3] [23]

تقدم [Dify](https://github.com/langgenius/dify) وظائف قوية للـRAG وسير العمل الوكيلي، بما في ذلك إدخال PDF وملفات أخرى، لكنني لم أضعها ضمن الخيارات الخمسة تحت معيار الرخصة المفتوحة المعتادة: رخصة المستودع تعديل على Apache-2.0 يضيف قيدًا على تشغيل خدمة متعددة المستأجرين، ويقيد إزالة شعار الواجهة وحقوق النشر. قد تناسب تثبيتًا داخليًا أحادي مساحة العمل، لكن افحص نص الرخصة مباشرة قبل بناء خدمة مستضافة أو منتج عليها.[20] [21] أظهر سجلها نشاطًا حتى 5 أكتوبر 2026.[22]
