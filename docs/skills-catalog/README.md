# كتالوج Skills من GitHub

## الغرض والنطاق

يوثق هذا المجلد طريقة اكتشاف Skills المستضافة على GitHub، وتقييمها، وقبولها للاستخدام في Agent Orchestrator. Skill خارجية هي محتوى غير موثوق، حتى لو كانت بصيغة Markdown أو جاءت من مستودع معروف؛ قد تحتوي تعليمات أو ملفات مساندة أو أدوات تؤثر في سلوك الوكيل أو بيئته.

هذه الوثائق **سياسة مقترحة وليست قائمة سماح أو موافقة على أي Skill**. لا يعني ظهور مستودع في تقرير بحث أنه اجتاز فحوص القبول الواردة هنا أو أنه آمن أو ملائم للدمج. لا تستورد Skill ولا تفعّلها قبل تنفيذ [سياسة القبول](acceptance-policy.md)، وتسجيل الأدلة والموافقة المطلوبة.

## الكتالوج الموحد والقرار

راجع [الكتالوج الموحد](catalog.md) للاختيارات المقارنة حسب التخصص، وروابط المصادر والرخص ودرجة الثقة وقرارات `adopt` / `reference` / `reject`. توصية `adopt` تعني مرشحًا لتكييف محدود بعد الفحص؛ **لا تعني أن Skill قد نُسخت أو قُبلت أو فُعّلت**. لا يزال كل مصدر يحتاج مراجعة نسخة محددة وقرار قبول مستقلًا وفق السياسة أدناه.

تقارير الأساس: [هندسة البرمجيات](research-coding.md)، [DevOps](research-devops.md)، [أمن البرمجيات](research-security.md)، [التعلّم الدفاعي](research-cyber-learning.md)، [UI/UX](research-uiux.md)، [تصميم الصور](research-image-design.md)، [تحرير الفيديو](research-video-editing.md)، [الصوت](research-audio.md)، [3D والألعاب](research-3d-games.md)، [البيانات والإنتاجية](research-data-productivity.md)، و[المنتج والبحث](research-product.md). سجل نتائج فحوص هذا الدمج في [verification.md](verification.md)؛ لا تعتبر نشاط GitHub أو رخصة المستودع دليلاً على اختبار أو قبول Skill بعينها.

## مسار القبول المختصر

1. اختر أصغر Skill لازمة لحاجة موثقة، وحدد مالكًا ومراجعًا.
2. ثبّت المصدر على commit كامل غير متغير، واجمع إثبات الرخصة وسجل provenance.
3. افحص محتوى التعليمات والموارد والاعتماديات بحثًا عن prompt injection، وأوامر خطرة، وبيانات حساسة، وحقوق نشر غير محسومة.
4. لا تشغّل hooks أو أوامر تثبيت أو سكربتات واردة من المصدر. افحصها ساكنًا فقط؛ أي اختبار تنفيذي لاحق يحتاج خطة وموافقة وعزلًا وفق السياسة.
5. احسب الدرجة، واجتز جميع بوابات الرفض الإلزامية، ثم نفّذ اختبارات ما قبل التفعيل في sandbox بلا أسرار أو صلاحيات إنتاج.
6. وثّق قرار قبول/رفض/تأجيل صريحًا. أي تحديث إلى commit آخر هو تغيير جديد يعاد فحصه واختباره.

راجع [سياسة القبول](acceptance-policy.md) للتفاصيل، بما فيها مقياس الدرجات وسجل الأدلة. لا يمنح القبول إذنًا بتنفيذ الأوامر التي توصي بها Skill؛ تظل صلاحيات الأدوات وموافقات المستخدم وسياسات المستودع مستقلة عنها.
